# تقرير التنظيف والتحقق النهائي

تاريخ الاعتماد: 4 أغسطس 2026

## ما تم تنظيفه

- إزالة أوامر الإصلاح والترقية والنشر التاريخية من جذر المشروع.
- إزالة تقارير الإصدارات المتكررة والأرشيفات القديمة وملفات البناء والكاش المحلية.
- تقليص سطح أوامر التطوير إلى أوامر واضحة داخل `package.json`.
- استبدال سلسلة التحقق التاريخية الطويلة ببوابة واحدة هي `tool/verify_project.py`.
- تثبيت أمر التنسيق على مسارات صريحة لمنع خطأ `Missing paths to code to format`.
- جعل بناء Web يستهدف JavaScript الحالي ويستخدم `--no-wasm-dry-run`، مع فحص ملفات الإصدار بعد البناء.
- حذف ملفات Dart غير القابلة للوصول والطبقات المكررة التي لم تكن مستخدمة في التطبيق.
- حذف اختبارات الإصدارات الهشة التي كانت تقرأ النص البرمجي وتبحث عن كلمات داخل الملفات بدل اختبار السلوك.
- الإبقاء على اختبارات Flutter السلوكية والوحدوية، ونقل العقود البنيوية الثابتة إلى أدوات Python المناسبة.

## إصلاحات معمارية إضافية

- منع اتصال الصفحات والـWidgets بـSupabase مباشرة؛ الاتصال يمر عبر Repository أو خدمة بنية معتمدة.
- نقل تحميل تفاصيل الأوامر التجارية من نافذة العرض إلى Repository ونموذج مستقل.
- فصل ثوابت أسماء المسارات في `lib/app/route_names.dart` لكسر دورات الاستيراد بين Router والصفحات.
- إضافة بوابة تمنع أي دورة Imports مستقبلية داخل ملفات Dart.
- جعل مستودعات الفترات التشغيلية والمحاسبة الاحترافية تنشر أحداث التحديث من طبقة البيانات نفسها.
- إزالة مصدر حدث زائد لم يكن له مستهلك داخل دورة التحديث.
- تصحيح ترتيب GitHub Actions: بناء Web أولًا ثم تجهيز CanvasKit المحلي وفحص الإصدار.

## النتيجة الحالية

- لا توجد دورات Imports بين ملفات Dart.
- لا توجد استدعاءات Supabase مباشرة داخل صفحات أو Widgets التطبيق.
- جميع Controllers طويلة العمر مسجلة مركزيًا أو موثقة كحالة محلية للصفحة.
- كل مصادر Mutation وRealtime لها مستهلك واضح في `AppDataRefreshCoordinator`.
- ملفات المصدر المحلية الحساسة والمجلدات المولدة مستبعدة من حزمة التسليم.
- بوابة `npm run verify` تنجح على الحزمة النظيفة.
