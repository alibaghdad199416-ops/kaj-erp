# حالة المتطلبات في حزمة التسليم

## مثبتة بعقود الفحص المحلي

- Supabase-only runtime مع Firebase Hosting-only.
- عمليات البيع والشراء المرتبطة والحذف المترابط.
- دفعات متعددة العملات: جزئية وكلية وتسوية.
- حزمة طباعة منفصلة لأمر البيع/الشراء والمخزن والفاتورة والدفعات.
- FIFO وطبقات كلفة المخزون في PostgreSQL migrations.
- أمر الصيانة وخدماته/مواده ومراجع المخزون والمحاسبة.
- سلة المحذوفات والاستعادة والحذف النهائي.
- تقارير PDF وExcel وCSV.
- Cash Flow تفصيلي عمودي ومشترك بين UI وPDF وExcel.
- تفضيلات الواجهة المعزولة لكل مستخدم.
- صور متعددة للسيارات والمنتجات مع ترتيب وصورة رئيسية.
- صلاحيات مخصصة لكل مستخدم.

## تحسينات V4 المطبقة في هذه الحزمة

- Design System مركزي.
- ثيم داكن وفاتح فاخر.
- شاشة دخول Responsive ومتصلة بمسار Supabase القائم.
- أسطح وبطاقات ونوافذ محسنة.
- قائمة جانبية وعلوية محسنة.
- Dashboard بلمسات KAJ الفيروزية والذهبية.
- عرض بصري أفخم للسيارات وقطع الغيار وصورها الديناميكية.
- منع العناوين المرئية المزدوجة عربية/إنجليزية في المواضع المكتشفة.
- بوابات تحقق حالية للبنية وقاعدة البيانات والمعمارية والترجمة ضمن `npm run verify`.

## يحتاج تحققًا على البيئة الحقيقية قبل الإنتاج

- أن جميع migrations المحلية مطبقة على مشروع Supabase المرتبط.
- أن Edge Functions منشورة بالإصدار المحلي نفسه.
- أن صلاحيات RLS تعمل مع حسابات الشركة الفعلية.
- سيناريوهات بيانات حقيقية لـFIFO والحذف المترابط.
- اختبار كل المتصفحات المستهدفة.
- فحص Firebase Preview قبل Production.
